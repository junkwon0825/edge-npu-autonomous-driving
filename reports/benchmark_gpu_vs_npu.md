# GPU vs Furiosa RNGD Benchmark (Phase 5) and Correctness (Gate E)

Evidence: `reports/evidence/gpu_vs_npu.json` (generated by `scripts/compare_gpu_npu.py`),
`reports/evidence/npu_bench.json`, `reports/evidence/gpu_benchmark_fp32_clean.json`, `reports/evidence/npu_compile.json`.

## What is identical between the two paths
- Model: fused YOLO26n split at the raw head (`YoloRaw`), same weights (SHA-256 `9b09cc8b…`), FP32 input tensors.
- Inputs: the same 72 CARLA frames, letterboxed to 640×640 **once on the Windows host** and shipped as uint8;
  both sides apply the same `to_tensor` function (identical file `yolo_raw.py`).
- Post-processing: GPU and NPU raw outputs are both decoded on the Windows host with the same `RawDecoder`
  + NMS (`conf 0.25`, `iou 0.7`, `max_det 300`). Class mapping: COCO ids, unchanged.

## What is NOT comparable (read before quoting numbers)
- **Execution style differs**: the GPU path is eager PyTorch (batch 1, launch-bound, ~24 % GPU util);
  the NPU path is an AOT-compiled graph (`CompileModule`). A compiled GPU path (CUDA Graphs/TensorRT) was not
  measured, so the latency ratio below is *not* a hardware-vs-hardware comparison.
- **Hosts differ**: GPU on the local Windows desktop; NPU on a remote shared Linux host (load average
  14–37 during runs). Network transfer to the remote host is excluded from all NPU numbers.
- **Precision**: GPU FP32. NPU inputs/outputs are FP32 tensors, but the compiler config has
  `implicit_type_casting: true`; the internal arithmetic precision on RNGD was not confirmed.
- Power: no reliable per-device power measurement was taken during inference (only the idle `furiosa-smi`
  reading of 39 W in the audit) → N/A.

## Numerical agreement

| Comparison | boxes max / mean abs | score-logit max / mean abs |
|---|---|---|
| NPU vs CPU (same host, same module) | 2.958 / 0.0324 | 5.566 / 0.0496 |
| NPU vs GPU FP32 (Windows) | 2.965 / 0.0322 | 5.352 / 0.0507 (max Δ sigmoid score 0.298) |

Raw tensors are **not** bit-close (large maxima, small means). The detection-level comparison decides
whether this matters:

| Split | Images | GPU dets | NPU dets | Matched (same class, IoU ≥ 0.5) | Recall vs GPU | Precision vs GPU | Mean IoU | Mean / max abs Δconf |
|---|---|---|---|---|---|---|---|---|
| eval | 54 | 254 | 253 | 251 | **0.988** | **0.992** | 0.991 | 0.0051 / 0.161 |
| calib | 18 | 94 | 95 | 94 | 1.000 | 0.989 | 0.991 | 0.0041 / 0.018 |

**Gate E verdict: PASS against tolerances set by the author at analysis time** (recall and precision vs the
GPU reference ≥ 0.95, mean matched IoU ≥ 0.95). These thresholds were not pre-registered. This is agreement
with the GPU model, not accuracy against ground-truth labels (no labelled set exists).
